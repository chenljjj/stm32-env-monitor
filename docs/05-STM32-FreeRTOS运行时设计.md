# STM32 FreeRTOS 运行时设计

任务、队列和互斥锁名称与源码标识保持一致。

本文说明 STM32 侧从 HAL 单循环迁移到 FreeRTOS 后的职责边界、同步策略与资源约束。

## 1. 任务和数据流

```text
             I2C1 mutex
 AHT20 ─┐        │
 BH1750 ├─> SensorTask ──> Display Queue ──> DisplayTask ──> SSD1306
        │                    Link Queue
        └───────────────────────└──────────> LinkTask ──> USART1 / ESP32
                                                    │
                                               ACK / NET_STATUS

 HealthTask ──> PC13 LED
 USART2 ──────> 可读调试日志
```

采样任务每秒形成一个完整快照。显示和链路任务各自持有一份队列消息，因此没有多个任务同时修改同一份可变测量结构。

## 2. 同步策略

- AHT20、BH1750、SSD1306 共用 I2C1，访问前获取 CMSIS-RTOS v2 互斥锁，访问结束后释放。
- 采集、显示和链路之间采用消息队列，而非裸全局变量。
- USART1 接收仍通过中断驱动。中断只向协议解析器写入字节，不调用 FreeRTOS 的 ISR 队列 API，因此使用的中断优先级不会违反 FreeRTOS 中断优先级限制。
- 当显示或通信队列满时，采集任务不等待，而是递增丢弃计数。环境数据是周期性遥测，“最新值优先”比阻塞后累积旧数据更合理。

## 3. 资源配置

| 项目 | 当前值 |
| --- | --- |
| FreeRTOS 接口 | CMSIS-RTOS v2 |
| 内存管理 | `heap_4` |
| FreeRTOS 堆 | 10240 字节 |
| 采样任务栈 | 1536 字节 |
| 显示任务栈 | 1536 字节 |
| 链路任务栈 | 2048 字节 |
| 健康任务栈 | 768 字节 |
| 每个快照队列长度 | 3 |

当前镜像可以链接并已完成实板基本功能验证，但 STM32F103C8T6 的 20 KiB SRAM 空间有限。后续应根据实际任务栈高水位和 FreeRTOS 剩余堆统计调整栈和队列大小，而不是仅依据编译通过判断安全。

## 4. 已验证与待验证

已验证：FreeRTOS 版本可编译、下载启动；AHT20/BH1750 采样、SSD1306 显示、USART1 ACK、ESP32 MQTT 上报均正常。OLED 已接收 `NET_STATUS` 快照并显示 Wi-Fi/MQTT 连接状态；最新居中排版已完成构建，需在重新烧录 STM32 后补充实板排版确认。

## 5. 运行时资源监控

链路任务在首个样本、随后每 60 个样本输出一行资源日志，例如：

```text
rtos heap=... min=... stack=.../.../.../... q=.../... peak=.../... qdrop=.../...
```

字段均不包含部署凭据，含义如下：

| 字段 | 单位 | 含义 |
| --- | --- | --- |
| `heap` | 字节 | 当前 FreeRTOS 可分配堆。 |
| `min` | 字节 | 自启动以来的最小剩余堆。 |
| `stack` | 字节 | `SensorTask`、`DisplayTask`、`LinkTask`、`HealthTask` 的最小剩余栈，顺序固定。 |
| `q` | 条 | 输出瞬间的显示/链路队列当前消息数。 |
| `peak` | 条 | 自启动以来的显示/链路队列最大消息数。 |
| `qdrop` | 条 | 队列满导致的显示/链路快照丢弃计数。 |

当前任务栈配置分别为 1536、1536、2048、768 字节，两个队列容量均为 3。正常长稳测试应满足：`min` 大于 0，四个 `stack` 值大于 0，`qdrop=0/0`；若 `peak` 达到 3 或某个栈高水位持续偏低，应先分析调度和日志，再增加栈或队列，不能仅凭编译通过判断安全。

同时已启用 FreeRTOS 堆分配失败与任务栈溢出检测。发生这两类不可恢复错误时，固件关闭中断并点亮 PC13 LED，以停止继续执行未知状态的业务逻辑。

## 7. 当前短时资源基线

一次约 65 秒的实板连续运行已观察到：启动阶段历史最小剩余堆为 2720 字节，业务任务稳定后当前剩余堆为 3344 字节；采样、显示、链路、健康任务的可用栈分别观测到 1140、896、864、644 字节；两个队列峰值均为 1，`qdrop=0/0`，UART ACK 与 MQTT 发布统计正常。

首次资源行中曾出现链路任务栈为 0。该行打印时全局 `LinkTask` 任务句柄尚未完成赋值，属于启动调度时机造成的采样缺口，而不是栈溢出；随后同一任务读数为 864 字节。后续长稳测试应从任务句柄均已就绪后的资源行开始记录，并以持续大于 0 的高水位为准。
