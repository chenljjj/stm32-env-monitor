# STM32 FreeRTOS 运行时设计

任务、队列和互斥锁名称与源码标识保持一致。

本文说明 STM32 侧从 HAL 单循环迁移到 FreeRTOS 后的职责边界、同步策略与资源约束。

## 1. 任务和数据流

```text
             I2C1 mutex
 AHT20 ─┐        │
 BH1750 ├─> SensorTask ──> Display Queue ──> DisplayTask ──> SSD1306
        │                    Link Queue
        └───────────────────────└──────────> LinkTask ──> USART1 / ESP32
                                                    │
                                               ACK / NET_STATUS

 HealthTask ──> PC13 LED
 USART2 ──────> 可读调试日志
```

采样任务每秒形成一个完整快照。显示和链路任务各自持有一份队列消息，因此没有多个任务同时修改同一份可变测量结构。

## 2. 同步策略

- AHT20、BH1750、SSD1306 共用 I2C1，访问前获取 CMSIS-RTOS v2 互斥锁，访问结束后释放。
- 采集、显示和链路之间采用消息队列，而非裸全局变量。
- USART1 接收仍通过中断驱动。中断只向协议解析器写入字节，不调用 FreeRTOS 的 ISR 队列 API，因此使用的中断优先级不会违反 FreeRTOS 中断优先级限制。
- 当显示或通信队列满时，采集任务不等待，而是递增丢弃计数。环境数据是周期性遥测，“最新值优先”比阻塞后累积旧数据更合理。

## 3. 资源配置

| 项目 | 当前值 |
| --- | --- |
| FreeRTOS 接口 | CMSIS-RTOS v2 |
| 内存管理 | `heap_4` |
| FreeRTOS 堆 | 10240 字节 |
| 采样任务栈 | 1536 字节 |
| 显示任务栈 | 1536 字节 |
| 链路任务栈 | 2048 字节 |
| 健康任务栈 | 768 字节 |
| 每个快照队列长度 | 3 |

当前镜像可以链接并已完成实板基本功能验证，但 STM32F103C8T6 的 20 KiB SRAM 空间有限。后续应根据实际任务栈高水位和 FreeRTOS 剩余堆统计调整栈和队列大小，而不是仅依据编译通过判断安全。

## 4. 已验证与待验证

已验证：FreeRTOS 版本可编译、下载启动；AHT20/BH1750 采样、SSD1306 显示、USART1 ACK、ESP32 MQTT 上报均正常。

待验证：长时间运行下的栈水位、堆碎片边界、队列峰值、ACK 丢失重传、ESP32 掉电以及队列满时的丢弃统计。
